# 開発・運用と画面仕様

利用手順は [README](../README.md)、解析・状態モデルは [architecture.md](architecture.md)、検証結果は [validation.md](validation.md) を参照。

## 実行環境と配信

UIはTypeScript、解析はWeb Worker上のPython / Pyodide、状態保存はIndexedDB。サーバーDBは使用しない。Google Drive同期を有効にした場合だけGoogleの認証・Drive APIを使用する。初回は同一ホストから約12MBのPyodideランタイムを取得する。本番ビルドは14ローカルリソースを含むPWAを生成する。

静的公開は `dist/` 一式をHTTPSで配信する。`BASE_PATH` 環境変数で配置パスを指定でき、未指定は `/`。`file://` での直接起動は非対応。インストールとオフライン確認は `npm run build` と `npm run preview` を使用する。

GitHub Pagesの `.github/workflows/deploy.yml` は `BASE_PATH=/woditor-review/` でビルドし、`dist/` を公開する。リポジトリのPages公開元はGitHub Actionsを選択する。`GOOGLE_CLIENT_ID` Secretがあれば、runner上だけで `.env.production.local` を生成する。設定ファイルとIDの値はコミットせず、配信するJavaScriptにだけ組み込む。クライアントシークレットやトークンは渡さない。

HTMLのリンクとWorkerはViteのbaseを使う。PWA生成時も同じVite設定からbaseを読み、Manifestのid・start_url・scope・アイコン、キャッシュ対象、ナビゲーションのフォールバックを揃える。Service Workerのスコープとキャッシュ名を配置パスごとに分け、他パスのキャッシュを削除しない。

Windowsでサブパスを検証する場合：

```powershell
$env:BASE_PATH = '/woditor-review/'
npm run build
npm run test:pages
npm run preview
```

このときのURLは `http://127.0.0.1:4173/woditor-review/`。ルート配置へ戻す場合は `Remove-Item Env:BASE_PATH` の後に再ビルドする。ビルドとプレビューでは同じ `BASE_PATH` を使用する。

## 読込仕様

右上メニューの「ファイルを読み込む」で、日本語と英語それぞれのZIPを指定します。例：

```text
japanese.zip
└─ ja-JP/texts/BasicData/CommonEvent/042.txt
english.zip
└─ en-US/texts/BasicData/CommonEvent/042.txt
```

余分な親フォルダ、`texts/` 始まり、`BasicData/`・`MapData/` 始まりも認識します。相対パスの重複・不正なパスは拒否します。ZIPは128MB、展開後のTXT合計は256MB、1 TXTは16MB、5,000 TXTまでです。

- `COMMON_ID=`、`TYPE_ID=`、`EVENT_ID=` で形式を判定し、Header・Map本体・タイルセット等はスキップします。
- UTF-8専用です。BOM・改行・空白・制御記号を保持します。
- 日本語のSlotを基準に、英語のキー・コマンド構造・文字列位置を照合します。
- 設定キーと前後のコマンド列から行ずれを補正します。無効化・削除された設定、英語版だけのコメントやコマンド、旧形式の追加引数は警告として記録し、入力を変更せず読み込みます。
- 対応候補が複数ある項目はエラーとして除外し、同じファイルの確実な項目は読み込みます。ファイル自体のIDや形式が異なる場合はファイルを拒否します。
- CSVの設定値は先頭列から項目0、1…として扱い、引用符付きの文字列だけをレビューします。データ名はDATANAME_LOAD_TYPE=0のときだけ、行末の`<<!--DATANAME--!>>`に続く文字列（最後のカンマを除く）を扱います。他のモードでは表示せず、タイプ参照も追跡しません。原文が空のセル・データ名は除外します。数値・ヘッダー・マーカー・列構造は保持し、引用符付きセル内のカンマ・二重引用符・実改行を扱います。データ名は引用符のない1行の文字列として保存します。表示用コマンドはコンテキスト専用で、翻訳単位とは分離します。
- 再度読み込むと既存レビューを照合・維持します。原文変更の対応が曖昧なファイルは適用せず、以前のデータを残します。

提供された328ファイルをすべて読み込み、13,589レビュー項目を生成します。原文の対応が曖昧な英訳14項目も原文を空にして登録し、周辺コマンドを参照して「原文を補う」から入力できます。補完内容は保存・バックアップ・再読み込みで保持します。日本語側の対応不明10箇所の診断記録は残します。各警告・エラーは [docs/validation-corpus.json](validation-corpus.json) に記録しています。

「読み込み結果 (エラー10)」のようにエラー件数を表示し、「エラー」「警告」「対象外」のタブで切り替えます。初期表示は「エラー」です。再読み込みが成功したファイルの古いエラーは置き換えます。

各診断をタップするとアプリ内のテキスト表示を開き、日本語・英語を切り替えて閲覧できます。行が特定できる診断は該当行（英語側は対応位置または近い周辺コマンド）へ移動して強調表示します。読み込めなかったファイルのテキストも端末内に保存し、再起動・バックアップ復元後も閲覧できます。古いバックアップに未解析ファイルの本文がない場合はZIPを再読み込みしてください。

## レビュー画面の動作

フォルダを展開してファイルを選びます。項目タイトルをタップすると項目一覧、下部のコメントボタンでコメントシートを開けます。

- 連続するコメントコマンドは1項目にまとめ、元のSlotを個別に保持します。
- コメント・変更履歴のないグループはメニューから行ごとに分割でき、隣接した同じ深さのコメントと結合できます。承認は解除されます。手動のグループ構成も保存・再読み込み・バックアップで維持します。
- 項目フィルターに応じて件数と前後移動を更新します。PCでは左右キーでも移動でき、入力中は干渉しません。
- 先頭・末尾で前後移動すると、フォルダビューのフィルターと自然順に従って前後のファイルを確認付きで開けます。別フォルダへ移る場合はフォルダ移動を確認します。移動先ではフォルダ側のフィルターを適用し、次へなら先頭、前へなら末尾の対象項目を開きます。
- 項目一覧の検索窓で原文・英訳・保留中の新訳を検索できます。検索は一覧の表示だけに適用し、下部カウンターと前後移動の対象件数には影響しません。
- ファイルを開くとフォルダビューの状態フィルターを項目一覧に引き継ぎます。項目側で変えたフィルターはフォルダビューへ戻しません。
- 項目一覧では項目名の下に原文の先頭1行を薄く表示し、長い原文は末尾を省略します。
- 未解決コメントがある項目は未確認です。承認するときは中央ダイアログで一括解決を確認し、次の対象項目へ移動します。
- 「コメントあり」フィルターでは、解決や承認で未解決コメントが0件になっても現在の項目を表示し続けます。対象件数は即更新し、表示項目が対象外ならカウンターは `0 / 対象件数` です。前後移動で次の対象へ離れます。ほかのフィルターでは承認後の自動移動を維持します。
- 「未確認に戻す」は確認後に実行し、表示項目を維持します。確認済みフィルターから外れた場合もこの項目を表示し、カウンターは `0 / 対象件数` になります。
- コメント・返信・解決・再開に対応します。自分の投稿は、その後にAI返信がない間だけ編集・削除できます。
- AIの再審で以前の案が不採用になった場合も回答JSONと元の英訳ZIPを読み込めます。「不採用の変更を破棄」で案を取り下げてからコメントを解決してください。破棄後も会話・変更履歴は残り、コメントを再開しても案は復活しません。再審で別の案が返った場合は、そのコメントの以前の保留案を置き換えます。
- コメントの「返信・編集・削除・解決」は1行に横並びで表示します。返信投稿の編集・削除も、その投稿の下に横並びで表示します。
- 項目・コメントのシートはハンドルから下スワイプで閉じます。内容部分はスクロール位置が先頭の場合に下スワイプで閉じます。
- セルフ変数は数値オペランドと `\cself[n]` の直接参照だけを表示します。間接参照は推測しません。
- 改行制御だけの差は薄い「改行が異なります」として表示します。それ以外の制御文字・置換文字列の差は通常の警告を表示します。

## 出力画面・通知・ファイル名

- レビューJSON出力は未解決コメントのあるファイルだけを列挙。英訳TXT出力は全ファイルを列挙する。「すべて選択」は各画面の対象だけを操作し、部分選択では indeterminate とする。
- JSONと英訳TXTの出力ボタンは同じ行。指示文はインライン表示せず、コピー通知の確認ボタンから中央ダイアログで全文を表示する。コピー拒否時も全文を手動コピーできる。Escapeで閉じ、Tabのフォーカスはダイアログ内に制限する。
- 原文・英訳・新訳ボックスは白。不採用案の説明と破棄ボタンは同じpair領域に置き、ボックスとの間に余白を設ける。承認ボタンは円で囲ったチェックアイコン。
- 依頼・回答のファイル名は `review_request_<短縮ID>.json` / `review_response_<短縮ID>.json`。UUIDのハイフンを除いた先頭12文字をファイル名に使用し、JSON内部のrequestIdは完全なUUIDを保持する。同じ出力シート内では依頼・コピー指示文でIDを共有する。
- バックアップ名は woditor-review-backup_YYYY-MM-DD_HH-mm-ss.json。端末のローカル日時で生成し、UTCへ変換しない。

## JSON形式とPython補助ツール

「AIレビューを依頼」は初回レビューとコメント回答を切り替える。従来の依頼はmode省略時もコメント回答として扱う。初回は `mode: "initial"`、`entries: []` とし、`targets` に選択したファイルの全項目・原文/英訳・版・既存スレッド・未確定案・周辺コマンドを含める。回答は `responses: []` と指摘だけの `suggestions`（changesは空）を返す。

初回レビューは問題箇所だけをAIの未解決スレッドとして追加し、英訳を変更しない。指摘なしでも自動承認しない。対象外項目・重複ID・再取り込み・依頼後の原文/現訳/項目構成変更・翻訳変更や修正ZIP付きの初回回答は全体を拒否する。指摘へ返信した後は従来のコメント回答・差分確定フローを使う。

Python補助ツールの初回レビュー用build入力は `{"responses":[],"suggestions":[{"path":"対象パス","itemId":"対象ID","reason":"指摘"}]}`。buildが指摘ID・版・空のchangesを補完し、validateで検証する。初回レビューではapplyを実行しない。

依頼・回答の `schemaVersion` は1です。

- [review-request.schema.json](schemas/review-request.schema.json)：依頼ID、相対パス、版（UTF-8 BOMを除いたテキストのSHA-256）、項目ID、Slot ID・英語側の位置・原文・現訳、コメントID・全投稿、周辺コマンド、再審用の保留案 `pendingChanges`。内部では日本語側の `line` と英語側の `enLine` を分離し、依頼JSONの `line` は英語側の行番号です。
- [review-response.schema.json](schemas/review-response.schema.json)：各コメントへの判断・理由・Slot別変更と新規改善案。既存IDと版をそのまま返します。
- バックアップ：`schemaVersion`、全ファイル、原文・英訳・BOM、Slot、グループ、コメント、保留／確定変更、依頼履歴、取り込み済み回答ID、診断情報を含みます。復元時に参照関係を検証します。

回答例（実際にはエクスポートしたIDと64桁の版を使います）：

```json
{
  "schemaVersion": 1,
  "requestId": "依頼ID",
  "responses": [{
    "commentId": "コメントID",
    "path": "BasicData/CommonEvent/042.txt",
    "itemId": "項目ID",
    "fileVersion": "依頼に含まれる64桁のSHA-256",
    "decision": "accepted",
    "reason": "表記を統一しました。",
    "changes": [{"slotId": "Slot ID", "before": "Old text", "after": "New text"}]
  }],
  "suggestions": []
}
```

`decision` は `accepted` / `rejected` / `partial` / `needs_review`。変更がなければ `changes: []` にします。保留案の維持・修正も `slots.translation` を変更前とする最終案を `changes` に指定し、撤回は `rejected` と `changes: []` で返します。回答は依頼の全コメントに1件ずつ必要です。同じSlotへの変更は1つの回答に集約します。新規改善案は依頼に含まれる項目を対象に `{id,path,itemId,fileVersion,reason,changes}` で指定します。

Python 3.10以降で、判断内容から形式を組み立て・検証できます。`decisions.json` は `responses` に `commentId,decision,reason,changes` を持ちます。パス・項目・版は依頼から補完します。

```powershell
python python/woditor_review_tool.py build --request review_request_ID.json --decisions decisions.json --out review_response_ID.json
python python/woditor_review_tool.py validate --request review_request_ID.json --response review_response_ID.json
python python/woditor_review_tool.py apply --request review_request_ID.json --response review_response_ID.json --english-root en-US/texts --out-root revised-texts
```

上記はリポジトリからの実行例です。`ID` は出力ファイル名の12文字の短縮IDに置き換えます。`apply` は英訳ファイルの版・変更前の文字列・保護トークンを検証し、新しい出力フォルダにのみ書き込みます。既存フォルダへの書き込みは拒否します。出力は回答に関係するファイルです。既存翻訳CLIも `python/woditor_translation_tool.py` で引き続き利用できます。

補助ツールを別の作業場所へ渡す場合は、python/ の woditor_review_tool.py・review_parser.py・review_alignment.py・database_csv.py・woditor_translation_tool.py と、隣接する docs/schemas/ の依頼・回答スキーマを同じ相対構成で用意する。指示文には実行時の作業場所を固定せず woditor_review_tool.py とだけ記載する。

## 構成

画面遷移はHistory APIと連動する。ファイル、シート、指示文プレビュー、確認ダイアログを履歴に記録し、戻る操作で手前の画面を閉じる。項目内の移動や表示条件の変更は現在の履歴を更新する。閉じるボタンやスワイプでも対応する履歴を戻し、後から同じパネルが再出現することを防ぐ。フォルダ画面からの戻る操作はブラウザへ委ねる。履歴には識別子だけを保存し、画面状態・コールバックはメモリ内に保持する。データ置換前の本文・確認処理は復帰させない。

コメントの下書きと返信・編集先は、同じ翻訳項目のパネルを閉じてもメモリ内で保持する。翻訳項目の切り替え、データ置換、送信成功、明示的な作成キャンセルで破棄する。再起動をまたぐ保存は行わない。

下部の「コメント」からは入力欄へフォーカスする。フロート表示からはプレビューと同じ投稿IDの位置へスクロールし、その投稿をフォーカスする。最新の返信も対象にし、履歴でパネルへ戻った場合も入力欄へフォーカスしない。

依頼モードと周辺コマンドの表示設定は、IndexedDBのmetaに `ui-preferences` として保存する。上下の初期表示行数（3〜10）、開閉、全体表示、言語、0始まりのコマンド番号、折り返しを端末ごとに保持し、履歴復帰で古い設定を上書きしない。全体表示では変数の全使用箇所をマークし、単一箇所の選択UIを隠す。長押しは500msでツールチップを表示し、離した際のクリックを抑える。通常のレビューJSON・バックアップ・Drive同期には表示設定を含めない。

出力対象の選択には自然順のフォルダ階層を使い、フォルダのチェックで配下を一括選択する。部分選択はindeterminateで示す。フォルダ画面のスクロールは項目画面と分けて保持し、項目一覧を開いたときは現在の項目を中央付近へ出す。

両出力パネルの範囲選択は、展開されているツリーの行順に沿う。Shift＋クリックは直前の通常チェック操作を起点とし、クリック先の選択・解除状態を範囲へ適用する。フォルダ行を含む場合は折りたたまれた配下も対象にする。タッチでは450msの長押し後に範囲選択を始め、選択済みの行から始めた場合は範囲を解除する。範囲を縮めると、範囲外はドラッグ開始時の状態へ戻す。上下端では一覧を自動スクロールし、指を離すと止める。長押し前のスワイプは通常のスクロールに委ねる。パネルを開き直す、依頼モードを変える、すべて選択を操作すると範囲の起点をリセットする。

読み込み結果は本文表示と項目への移動を別ボタンにする。行番号のある項目は同じSlotを優先し、設定削除などで該当項目がなければ「近くの翻訳項目」を示す。原文未特定のエラー行は英語側の番号として扱う。解析できなかったファイルは本文だけを開く。項目リンクからブラウザで戻ると元の結果タブへ戻る。

「自動補正」は行ずれの対応付けと既知の旧形式差の吸収だけに使う。欠落・追加・設定値やコマンド引数の違いは「警告」とし、翻訳項目・設定・コマンドを別の単位で集計する。翻訳項目の欠落は抽出済みの文字列スロット数で数え、同じコマンドに複数の対象文字列があればそれぞれ数える。設定値の差は英語側を変更したという表現を避け、CSVの数値・非文字列も同様に扱う。

DBの選択肢名とCSV設定値には、英訳の下に対応するITEMNAMEの原文・英訳を表示する。CSV列とCHOICE_NAMEの最初の番号を0始まりの項目番号として照合する。コモンのCHOICE_STRの選択肢には対応するVALINPUT_NAMEの原文・英訳を表示する。項目番号・引数番号の補助ラベルは表示しない。原文は元のTXTヘッダーから読み取り、英訳は同キーの現在の確定値を優先する。SlotがないASCII名等もヘッダーから取得し、本文との区別に薄い灰色の背景を使う。周辺コマンドと同じ開閉ボタンを使い、開閉状態は共通の表示設定として保存する。

DB項目名・コモンの数値引数名には、対応する選択肢だけを原文・英訳の2列の罫線付きリストで表示する。番号列は付けず、本文と同じ14pxの文字サイズを使う。CSVのデータ値は表示しない。各言語の有効件数を反映し、片側にだけ有効な選択肢も対応なしと明記して残す。選択肢がなければリストは表示しない。折りたたみ状態は対応項目・引数表示から独立して保存する。

DBの翻訳項目は、各データ名を同じデータ番号の設定値の前へ並べる。一覧・前後移動・承認後移動・カウンターを同じ表示順に揃え、フィルターでデータ名が除かれた場合は残る項目の順序を保持する。保存済みのitemsや文字列スロットの順序、TXT内の位置は変更しない。

キーボード表示時は `interactive-widget=resizes-content` を指定し、VisualViewportの高さ・オフセットをアプリとシートの寸法へ反映する。html/bodyを固定して外側へのスクロールを防ぎ、パネル内の内容だけスクロールさせる。ピンチズームではレイアウト寸法を保持する。仕様の背景は [Chromeのビューポート変更](https://developer.chrome.com/blog/viewport-resize-behavior/) と [VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport) を参照。コメントのスクロール矢印はscrollとResizeObserverで更新する。

日本語の太字フェイスを持たない端末でも見出しを太く表示できるよう、`font-synthesis: weight` を許可する。主要なラベル・ボタン・項目名は700を指定し、本文は通常の太さを保つ。外部Webフォントは取得しない。

## Drive同期の実装

- `drive-auth.ts`：Google Identity Servicesを同期画面から遅延ロードする。接続ボタンのクリックから同期的に認可ポップアップを開き、アクセストークンはメモリ内だけに保持する。更新トークンは取得・保存しない。
- `drive-api.ts`：`drive.appdata` スコープの専用フォルダにgzipスナップショットを追加する。メタデータを作るresumableセッションのPOST後に本文をPUTする。ダウンロードは展開後256MiBまでのストリームで読み、通常バックアップと同じ参照検証を通す。ページ分割された一覧をすべて取得する。
- `drive-sync.ts`：各スナップショットはUUIDと親版のUUIDを持つ。親はDriveの`appProperties.p0`以降にも記録し、後続のない版を同期候補として扱う。更新は既存の版の置換ではなく新規追加。同時保存は複数候補として残り、明示的な選択を全候補を親に持つ新しい版で記録する。選択後に別の版が追加されていた場合は再選択を求める。履歴の自動削除はしない。
- 端末の基準版はクライアントID・GoogleアカウントID別に保存する。ワークスペースのSHA-256はトップレベルの`updatedAt`だけを除外する。一方だけの変更は送受信し、双方の変更・複数候補・異なる初期データは競合とする。項目単位での自動マージはしない。
- `drive-controller.ts`：1分ごとの自動同期は任意設定で初期値は無効。アプリ表示中、他のシートや編集中の画面がない場合だけ実行する。受信中に端末が変わっていたら反映を止める。受信直前の端末データをIndexedDBに1件保存し、バックアップとして回収できるようにする。通信失敗や認証切れで端末データを消さない。
- クライアントID、自動同期設定、基準版、復旧用コピーはIndexedDBの`meta`に保存する。Googleトークンやこれらの接続設定は通常のレビューJSON・ワークスペースバックアップ・Driveスナップショットに含めない。
