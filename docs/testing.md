# テストの構成と実行

通常テストは `.reference` やGoogleアカウントなしで実行する。Python 3.10以降、Node.jsとnpm依存、Playwrightの実行用ブラウザーが必要。Pythonは標準ライブラリだけを使用する。環境設定は [development.md](development.md#検証) を参照。

## 実行

```powershell
npm test
npm run test:python
npm run build
npm run test:e2e
```

`npm run check` は整形チェック・lint・型検査、Python・TypeScript単体、本番ビルド、ルート配置のE2Eを順に実行する。事前に [development.md](development.md#開発ツールの準備) の開発用venvを用意する。サブパスの確認は別の本番ビルドを使い、先に起動したpreviewサーバーを停止してから実行する。

```powershell
$env:BASE_PATH='/woditor-review/'
npm run build
npm run test:pages
Remove-Item Env:BASE_PATH
```

サブパスの検証後に通常の開発へ戻る場合は、通常の `npm run build` で成果物を戻す。UI変更時だけ、既存の `UPDATE_SCREENSHOTS` による撮影手順を使用する。テストを移動しただけの場合は画像を更新しない。

バックアップのメモリ比較はWindows/Edgeで `node scripts/benchmark-backup.mjs` を実行する。専用のViteサーバー（127.0.0.1:4175）とブラウザーを起動し、私有データを使わず160ファイル・10,240項目を生成する。旧JSON出力と分割ZIP出力を各3回計測し、全ブラウザープロセスのPrivate Bytes・Working Set（Worker・ネイティブBlobを含む）、出力サイズ・時間、URL解放とGC後の保持を `.tools/quality-audit/backup-memory.json` に記録する。出力先は第1引数で変更できる。旧処理のURL解放を待つため数分かかる。計測中は別のテストを並行実行しない。OSの予約メモリと生存オブジェクトを区別し、単なるメイン画面のヒープ減少だけで改善と判断しない。

## 検証の分担

| 層              | 主な保証                                                                                                                                                           |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| TypeScript単体  | レビュー状態・AI回答の原子的な拒否と確定/再開/破棄、上書き時の保全、バックアップの参照検証、ZIPパス、検索・並び順・移動、同期の競合・認証/API処理                  |
| Python単体・CLI | TXT/CSV解析、抽出対象、日英の対応付けと位置、特殊文字列、未使用設定の検出・安全な削除、無変更往復、文字コード/BOM/改行、別フォルダへの出力、単体配布と内包スキーマ |
| PC・モバイルE2E | ZIPから実際のPyodide解析・表示・保存・再起動・出力、AIレビューの往復、キャンセルと履歴、フィルター・選択・関連項目、設定保持、Driveの端末間同期、操作可能性        |
| Pages E2E       | サブパスのアセット・Manifest・Service Workerと、オフラインで初めてPythonを起動する解析・保存・JSON出力・バックアップ圧縮Worker                                     |

タッチのドラッグ選択・スワイプはモバイルだけで実行する。キーボード表示はVisualViewportの縮小・移動で再現し、入力欄の収まりと外側スクロール防止を確認する。実端末のキーパッドやiOSの挙動まで保証するものではない。Driveの認証・APIはモックであり、実アカウントの認可は [google-drive.md](google-drive.md) の手順で別途確認する。

## 入力データと共通処理

- `tests/fixtures/woditor.json` は実ゲームの文章を使わずに構成した日英の最小TXT/CSV。連続コメント、複数の変数使用箇所、英語側の追加、曖昧な対応、旧形式、DBのCSV・未使用設定を含む。TSとPythonで同じ入力を使うが、期待値を製品コードから生成しない。
- `tests/helpers/` のモデルはTypeScriptの状態・対応付けテストの入力専用。Pythonや製品パーサーを起動せず、TXTとの受け渡しはPython/E2E側で確認する。特定の境界条件だけが必要な小さなfixtureは、該当テストの近くに置く。
- Pythonの共有入力は `tests/python/fixtures.py`、ブラウザーのファイル読込み・移動・コメント・依頼などは `tests/browser/helpers.ts` に置く。specやtestモジュールから別のテストへfixtureを輸入しない。
- 文字コード・BOM・CRLFや、スクロール・複数ファイルに必要な件数は各テストで明示的に生成する。共有データに大量の無関係な行を増やさない。
- ブラウザーのspecは機能別に分ける。操作ヘルパーにはケース固有の期待値や、失敗を見えなくする自動再試行を入れない。

## 2026年11月13日の整理判断

| 対象                                                      | 判断と検出能力の維持                                                                                                             |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 実データがないと省略されていたレビュー・CLI・Drive・Pages | 最小データへ置換し、通常テストで常に実行する                                                                                     |
| 実データ全件の解析・位置・書き戻し・削除検査              | 代表する各形式の不変条件と、入力形式/件数の境界ケースへ移す。Worker・複数ファイル・フォルダ復帰は45ファイルの生成ZIPで確認する   |
| 初回レビュー・上書きの単体テストの重複                    | 専用テストへ集約する。版/Slot/保留案の不一致、拒否時の無変更、未変更案の維持、旧コメントによる巻き戻り防止は残す                 |
| 表示用の改行・引用符と色分け                              | 表形式の入力・期待値と、言語/インデントの振る舞いを検証する。製品の色テーブルをそのまま期待値として反復しない                    |
| 三角のSVG形状、ドットの色/寸法、バッジや余白の座標        | 独立ケースや細かなassertを削除する。内容・状態・操作可能性のテストと、必要時の目視確認を使用する                                 |
| 診断のテキスト表示・戻る操作                              | タブとスクロール復元のケースへ日英別の該当行・長文閲覧を集約する。不正ファイルの保存後閲覧、項目への移動、原文補完と再起動も残す |

旧データセットの全ファイルについての件数や網羅性は、通常テストの保証ではない。既知の仕様・不具合を表す最小入力を追加して維持する。従来の全件調査の記録は [validation.md](validation.md)、必要に応じた調査スクリプトは `scripts/corpus-report.py` に残すが、自動テストからは呼ばない。
