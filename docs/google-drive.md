# Google Drive同期の設定と運用

## サイト管理者の初期設定

1. [Google Cloud Console](https://console.cloud.google.com/)でプロジェクトを作成・選択し、APIライブラリで **Google Drive API** を有効にする。
2. **Google Auth Platform** でアプリ名・連絡先・対象ユーザーを設定する。テスト公開中は、同期に使うGoogleアカウントをテストユーザーへ追加する。
3. データアクセスのスコープに次を設定する。
   - `https://www.googleapis.com/auth/drive.appdata`：このアプリ専用の同期データ。
   - `openid` と `email`：接続アカウントの識別・メールアドレス表示。
4. **クライアント**からOAuthクライアントを作成し、種類を **ウェブ アプリケーション** にする。
5. **承認済みのJavaScript生成元**に、アプリを開くURLの生成元（スキーム・ホスト・ポート）を登録する。パスは付けない。例：開発の `http://localhost:5173`、`http://127.0.0.1:5173`、プレビューの `http://127.0.0.1:4173`、本番サイトの `https://example.github.io`。実際に使う生成元をそれぞれ登録する。
6. 作成した `…apps.googleusercontent.com` のクライアントIDを、アプリの「Google Drive同期」→「接続設定」に入力して保存する。クライアントシークレットは使わない。

これはブラウザからGoogle Identity Servicesのポップアップで認可する方式。サーバー、APIキー、サービスアカウントは不要。同じGoogle Cloudプロジェクトの同じクライアントIDを、同期させる端末で使用する。

サイト側にIDを組み込む場合は `.env.example` を `.env.local` へコピーし、`VITE_GOOGLE_CLIENT_ID` に実際のIDを設定してからビルドする。Viteを起動済みなら再起動する。公開してよいクライアントIDだけを設定し、トークンやシークレットは書かない。埋め込みIDがある場合は保存済み設定より優先し、接続設定の入力欄を表示しない。埋め込みIDがない場合だけ、各端末でIDを入力・保存する。

Googleの設定は[公式セットアップ手順](https://developers.google.com/identity/oauth2/web/guides/get-google-api-clientid)を参照。

## 利用手順

1. 1台目の端末でTXTを読み込み、メニュー「Google Drive同期」を開く。
2. 「Googleに接続」でアカウントと権限を確認し、「今すぐ同期」を押す。
3. 2台目も同じクライアントIDで同じGoogleアカウントに接続し、「今すぐ同期」を押す。まだデータがない端末にはDriveの状態を読み込む。
4. 必要に応じて「アプリを開いている間、1分ごとに自動同期」を有効にする。コメント入力や別の操作画面を開いている間、非表示のタブでは自動同期を待機する。

同期対象は原文・英訳、レビュー項目、コメントと会話履歴、承認、変更案、依頼・回答履歴、読み込み診断。表示中の項目や開閉状態は端末ごとのまま。

端末とDriveの両方に変更がある場合や、別々のプロジェクトを同期しようとした場合は、自動で結合・上書きせず選択画面を表示する。選択はレビュー全体の状態に対して行う。Driveから採用する直前の端末データは復旧用に1件保存し、同期画面の「同期前の端末データをバックアップ保存」から取り出せる。必要なら通常の「バックアップを復元」で戻せる。

接続解除・再読み込みでアクセストークンを破棄する。期限切れや通信失敗でローカルの作業を削除しない。再接続後に同期をやり直せる。バックグラウンドやアプリ終了中の同期には対応しない。

## 保存先・履歴

同期にはDriveの非表示の `appDataFolder` を使う。他のDriveファイルを読む権限は要求せず、同期データは通常のDriveファイル一覧には表示されない。[アプリ専用領域の説明](https://developers.google.com/workspace/drive/api/guides/appdata)

既存の版を上書き・削除せず、圧縮した状態を新しい版として追加する。同時に複数の端末が保存しても、双方の版を残して次の同期で競合を表示する。採用した版を記録してから同期を続ける。

履歴は自動削除しないため、保存量は同期に伴って増える。Drive上の履歴を全削除する場合は、Drive設定のアプリ管理から本アプリのデータを削除する。端末側のデータとファイルによるバックアップは独立して残る。

## 検証範囲

自動テストではGoogle Identity ServicesとDrive APIをモックし、実際のTXT・保存処理を使って2つのブラウザ環境間で同期する。OAuthクライアントIDは利用者が作成するため、実Googleアカウントでの認証・実Driveへの保存は未検証。初期設定後、少量のデータで2端末の同期と復旧用バックアップを確認する。
